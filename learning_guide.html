Iteration 1 — The Big Picture

What Did We Do and Why Does It Matter?

The Problem

Hate speech on social media disproportionately affects non-English communities. Automated detection systems are almost entirely built for English. Roman Urdu — Urdu typed in the Latin alphabet — is how most Pakistanis write informally online. Existing systems are blind to hate speech in this form.

Roman Urdu example: "Yeh log bohat bure hain" — this is Urdu written in English letters. No standard spelling rules. Mixed English-Urdu vocabulary. Culturally specific insults that don't appear in English datasets.

Our Approach

We used Transfer Learning: take a model already trained on English hate speech and try to make it work on Roman Urdu — without collecting thousands of labelled Roman Urdu examples.

Three Key Findings

Finding 1 — Bigger models are better on English.
The largest model (XLM-R-large) correctly identified hate speech more often than smaller models on English test data.
Finding 2 — Zero-shot transfer completely fails.
When we pointed the English-trained model at Roman Urdu without any additional training, it almost never flagged anything as hate speech. It learned what English hate looks like, not what hate looks like.
Finding 3 — Standard few-shot training collapses to all-hate.
Giving the model just 8–64 labelled Roman Urdu examples caused it to swing to the opposite extreme — flagging everything as hate (FPR ≈ 1.0). Even using balanced class weights [1.0, 1.0] could not prevent this collapse at K ≤ 32.
Finding 4 — Prompt-based fine-tuning breaks the collapse.
By reframing classification as masked-word prediction — appending "This text is [MASK]." and using the pre-trained MLM head — we avoid the random-init problem. At K=64: Macro F1 jumps from 0.528 → 0.745, FPR drops from 0.777 → 0.355.
Finding 5 — Classical ML and supervised fine-tuning achieve best results.
TF-IDF + FuzzyWuzzy similarity features + Logistic Regression (full Urdu training set) reaches Hate F1 = 0.857, Macro F1 = 0.841. Full supervised fine-tuning of XLM-R-large on all 7,208 Urdu samples achieves Hate F1 = 0.895, Macro F1 = 0.885 — the project's best result.
Finding 6 — The model is biased against religion.
Text mentioning religion was flagged as hate speech 5× more often than average, even when it wasn't hateful. The model learned religious words as hate signals from English training data.

4. Why F1 Score, Not Accuracy?

F1 Score = the harmonic mean of Precision and Recall.

Precision: Of everything I flagged as hate, how many actually were? (avoids false alarms)
Recall: Of all actual hate, how much did I catch? (avoids missing hate)
F1: 2 × (Precision × Recall) / (Precision + Recall) — you need both to be high.

6. What Is Prompt-Based Fine-Tuning?

Standard fine-tuning adds a brand-new classification head (2 output neurons, randomly initialised) on top of the transformer. With only K=8 examples, the random head overwhelms the pre-trained features. Prompt-based fine-tuning avoids this by reframing the task as a fill-in-the-blank problem the model already knows.

Input tweet:
"Yeh log bure hain"
→
Append template:
"Yeh log bure hain
This text is [MASK]."
→
MLM head predicts [MASK]:
hate/bad/vile → HATE
normal/okay/good → SAFE
Why it works: The MLM head has been trained on 2.5 TB of text to predict masked words. It already knows "hate" and "normal" are semantically related to hostile vs. neutral content. A randomly-initialised classification head has no such prior knowledge — it must learn from scratch, which fails catastrophically with only 8–64 examples.

7. What Is TF-IDF + FuzzyWuzzy?

Before deep learning, text classification used hand-crafted features. We combined two types:

  • TF-IDF (Term Frequency–Inverse Document Frequency): turns each tweet into a bag-of-words vector, weighting rare words higher. A word common everywhere (like "the") gets near-zero weight; a word rare but specific to hate (like a slur) gets high weight.
  • FuzzyWuzzy similarity: computes how similar each tweet is to a set of known hate phrases using fuzzy string matching. Handles spelling variation common in Roman Urdu (same word spelled 5 different ways).
Result: TF-IDF + FuzzyWuzzy + Logistic Regression on the full Urdu dataset achieves Hate F1 = 0.857 — beating the few-shot transformer methods. This confirms that Roman Urdu hate speech is quite lexically distinctive, and simple word-counting captures that signal efficiently when enough labelled data is available.
Iteration 3 — Under the Hood

Transformers, Training, and the Collapse

1. How Text Becomes Numbers (Tokenization)

Neural networks only understand numbers. XLM-R uses SentencePiece — it breaks words into subword pieces, each mapped to an integer ID, then to a 1024-dimensional vector.

Subword example:
"hatred" → [hat, red] → [1423, 892] → two 1024-dim vectors
"bure" (Roman Urdu) → [bur, e] → two 1024-dim vectors

Why subwords? No single vocabulary can contain every word in 100 languages. Subwords handle unknown words by decomposing them into known pieces.

4. Class-Weighted Loss — Solving the Imbalance

Without weighting: a model that says "not hate" always gets loss ≈ 0.05 — it never learns. We upweight hate samples by 8×:

Loss = −Σ w[yᵢ] · log p(yᵢ | xᵢ) Where w = [1.0, 8.0] (non-hate, hate) Missing a hate sample costs 8× more than missing a non-hate sample. The model can no longer afford to ignore the minority class.

5. Why Few-Shot Collapsed — The Root Cause

The mismatch (first hypothesis): We initially used class weight w_hate = 3.0 (calibrated for English's 5.2% hate) on Urdu data that is 53.5% hate — already nearly balanced. With w_hate = 3.0 on balanced data, the model minimises loss by predicting everything as hate. Reducing to w = [1.0, 1.0] reduced collapse severity, but standard few-shot fine-tuning still collapsed at K ≤ 32.
The deeper cause (confirmed): Standard fine-tuning adds a randomly-initialised 2-neuron classification head. With K=8 examples, the noisy gradients from this random head corrupt the pre-trained backbone's representations in the first few steps. With balanced data and K≤32, the easiest gradient path is always "predict all hate" — this minimises the loss without learning discriminative features. This is a degenerate global minimum that even balanced class weights cannot escape.

5b. Prompt-Based Fine-Tuning — The Fix

Key insight: Instead of a random classification head, use XLM-R's pre-trained Masked Language Modelling (MLM) head. Append the template "{tweet} This text is [MASK]." and predict the [MASK] token. Map predicted token probabilities to class probabilities via a verbalizer:
Verbalizer mapping: HATE class → tokens: {"hate", "bad", "wrong", "vile", "terrible"} NON-HATE class → tokens: {"normal", "fine", "okay", "good"} Loss function: p(HATE) = log-sum-exp of MLM log-probabilities for hate tokens p(NON-HATE) = log-sum-exp of MLM log-probabilities for non-hate tokens L = CrossEntropy(p(HATE), p(NON-HATE), true_label) Why this avoids collapse: The MLM head already assigns p("hate") > p("normal") for hateful text, even before any few-shot training. Gradient signal is meaningful from step 1, rather than random noise from a new head.
Result: At K=64, Macro F1 rises from 0.528 (standard FT) → 0.745 (prompt-based). FPR drops from 0.777 → 0.355. At K=32, Macro F1 rises from 0.349 → 0.634 — the gap is even larger, confirming that prompt-based is most helpful when data is scarce.

File 3: scripts/train.py — The WeightedTrainer

# Subclass HuggingFace Trainer — only override compute_loss
# Everything else (gradient accumulation, fp16, checkpointing) stays as-is
class WeightedTrainer(Trainer):
    def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
        labels = inputs.pop('labels')    # pull out labels manually
        outputs = model(**inputs)          # forward pass
        weights = torch.tensor(
            [1.0, 8.0],                    # non-hate, hate
            device=outputs.logits.device   # MUST be on same GPU as model
        )
        loss = torch.nn.CrossEntropyLoss(weight=weights)(
            outputs.logits, labels
        )
        return (loss, outputs) if return_outputs else loss

# Template: append fill-in-the-blank prompt to every tweet
TEMPLATE = "{text} This text is {mask_token}."

# Verbalizer: map word tokens to class labels
# Confirmed all tokens are single SentencePiece pieces (no splitting)
HATE_WORDS    = ["hate", "bad", "wrong", "vile", "terrible"]
NONHATE_WORDS = ["normal", "fine", "okay", "good"]

# Forward pass: get MLM logits at [MASK] position
def verbalizer_loss(model, input_ids, attention_mask, labels):
    mask_pos = (input_ids == MASK_ID).nonzero(as_tuple=True)[1]
    out = model(input_ids=input_ids, attention_mask=attention_mask)
    logits = out.logits[range(len(mask_pos)), mask_pos]  # [B, vocab]

    # Log-sum-exp: aggregate probabilities for each class's word set
    p_hate = torch.logsumexp(logits[:, hate_ids],    dim=-1)  # [B]
    p_safe = torch.logsumexp(logits[:, nonhate_ids], dim=-1)  # [B]
    class_logits = torch.stack([p_safe, p_hate], dim=1)       # [B, 2]

    return torch.nn.CrossEntropyLoss()(class_logits, labels)

1. log-sum-exp aggregation is used (not mean) because log-probabilities are in log-space — summing exps then taking log is numerically stable and correctly combines probabilities.

File 6: scripts/classical_baseline.py — TF-IDF + FuzzyWuzzy

from sklearn.feature_extraction.text import TfidfVectorizer
from fuzzywuzzy import fuzz
from sklearn.linear_model import LogisticRegression

# 1. TF-IDF features: bag-of-words with subword n-grams
#    char_wb = character-level n-grams within word boundaries
#    handles Roman Urdu spelling variation ("bura"/"boora"/"booraa")
tfidf = TfidfVectorizer(ngram_range=(1,3), analyzer='char_wb', max_features=50000)
X_train = tfidf.fit_transform(train_texts)

# 2. FuzzyWuzzy: fuzzy string similarity to prototype hate phrases
#    Returns 0-100 similarity score; handles spelling noise
def fuzzy_features(text, prototypes):
    return [fuzz.partial_ratio(text, p) / 100.0 for p in prototypes]

# 3. Concatenate TF-IDF + fuzzy → train Logistic Regression
#    LR is fast, interpretable, and competitive on lexical tasks
clf = LogisticRegression(C=1.0, max_iter=1000)
clf.fit(np.hstack([X_train.toarray(), fuzzy_train]), y_train)
Why classical ML works so well here: Roman Urdu hate speech is highly lexical — specific words and phrases recur frequently across hate samples. TF-IDF captures these word patterns directly. FuzzyWuzzy handles the highly variable spelling (e.g. "kafir", "kaafir", "kafer" all map to similar fuzzy scores). With 7,208 training examples the vocabulary is well-covered, and Logistic Regression can separate the classes cleanly. Result: Hate F1 = 0.857, beating all few-shot transformer methods.

The Mathematics Behind Every Decision

1. Why XLM-R Beats mBERT — Three Specific Reasons

PropertymBERTXLM-R
TokenizerWordPiece · 119K vocab · Wikipedia onlySentencePiece BPE · 250K vocab · Common Crawl (web)

2. Learning Rate Schedule — The Exact Math

Training setup: 21,159 EN samples · batch size 8 · gradient accumulation 4 steps per epoch = ⌈21159 / 8⌉ = 2645 update steps / epoch = ⌈2645 / 4⌉ = 662 total updates (5 ep) = 662 × 5 = 3310 warmup steps = 0.1 × 3310 = 331 Learning rate schedule: LR(step) = lr_max × step/warmup for step ≤ 331 LR(step) = lr_max × (3310-step)/2979 for step > 331 Why warmup? At step 0 the classifier head is random → large noisy gradients. Warmup lets the head stabilise before full LR hits the pre-trained backbone's 560M parameters.

3. Weight Decay — Preventing Overfitting

Total loss with weight decay (λ = 0.01): L_total = L_cross_entropy + λ · Σ θᵢ² Penalises large parameter values → prevents memorising training data. Applied as AdamW: weight decay directly on weights, not via gradient (more principled than L2 regularisation in Adam).

4. fp16 — Half Precision Training

FormatBytes/numberRangeXLM-R-large weights
fp32 (default)4 bytes~1.2×10⁻³⁸ to 3.4×10³⁸560M × 4 = 2.24 GB
fp16 (we use)2 bytes~6×10⁻⁸ to 65504560M × 2 = 1.12 GB
Risk: Small gradients round to zero in fp16 (underflow) → model stops learning.
Fix: Automatic Mixed Precision (AMP) — multiply loss by 1024 before backprop, divide gradients by 1024 after. This shifts magnitudes into the representable range.

5. Gradient Checkpointing — Memory vs Speed

Normal training: Forward pass → store ALL 24 layers' activations → Backward pass uses them Memory: O(layers × sequence_length × hidden_size) Gradient checkpointing: Forward pass → discard activations → Backward pass RECOMPUTES them on the fly Memory: O(1) activations stored Cost: ~33% slower (forward pass runs twice effectively) We used it for English training (560M model, long sequences). Disabled for few-shot (tiny batches, no memory pressure).

6. Class Weight Loss — Full Gradient Derivation

For a hate sample (y=1) incorrectly predicted with p(hate)=0.05: Standard gradient: ∂L/∂logit = p_c - 1[c==y] ∂L/∂logit_hate = 0.05 - 1 = -0.95 (push hate logit up) Weighted gradient (w_hate = 8.0): ∂L/∂logit_hate = 8.0 × (0.05 - 1) = -7.6 (8× larger update!) The model receives 8× larger gradients for missed hate samples. This forces it to prioritise hate recall over non-hate accuracy.

7. Few-Shot Collapse — Mathematical Proof

Urdu: 53.5% hate, 46.5% non-hate. K=8 batch: 4 hate, 4 non-hate. Class weights: w_non_hate=1.0, w_hate=3.0 Strategy A — predict ALL non-hate: 4 hate wrong: 4 × 3.0 × (-log ε) ≈ 12 × large 4 non-hate right: 4 × 1.0 × 0 = 0 Total loss ∝ 12 × large Strategy B — predict ALL hate: 4 hate right: 4 × 3.0 × 0 = 0 4 non-hate wrong: 4 × 1.0 × (-log ε) ≈ 4 × large Total loss ∝ 4 × large Strategy B has 3× LESS loss → gradient descent finds it in a few steps. This is a global minimum of the loss. No random seed can escape it. With balanced weights w = [1.0, 1.0]: Strategy A loss ∝ 4 × large Strategy B loss ∝ 4 × large ← equal! Equal degenerate loss with balanced weights means gradient descent no longer has a preferred degenerate solution. BUT the randomly- initialised classification head still produces near-uniform logits initially, and with K=8 the gradient signal is noisy enough that the model still collapses in practice. Experimental confirmation: K=32, w=[1.0,1.0]: Macro F1=0.349, FPR=1.000 (still collapsed) Why prompt-based avoids this: MLM head already knows p("hate"|hateful context) >> p("hate"|neutral) → meaningful gradient from step 1 → no degenerate local minimum.

Quick Reference Glossary

Pre-trainingTraining a model on massive unlabelled text to learn language itself. Done once by large labs; we reuse the result.
Fine-tuningTaking a pre-trained model and training it on labelled task data. Updates all parameters with a small learning rate.
TokenizationBreaking text into subword pieces (tokens) and mapping each to an integer ID → embedding vector.
Self-attentionMechanism allowing every token to attend to every other token; lets the model understand context (negation, sarcasm, targets).
Class-weighted lossMultiplying the loss for the minority class (hate) so missing it costs more. Forces the model to learn the rare class.
Zero-shot transferApplying an English-trained model to Urdu without any Urdu training examples.
Few-shot (K-shot)Giving the model K labelled Urdu examples to adapt to the new language.
Hate F1Primary metric: harmonic mean of hate precision and hate recall. Robust to class imbalance.
FPR (False Positive Rate)FP / (FP + TN). How often non-hate is wrongly flagged. Fairness metric.
Gradient accumulationSimulate a large batch size by accumulating gradients over several small batches before updating weights.
fp16Half-precision training: halves VRAM usage, 2× faster, minor precision loss compensated by AMP loss scaling.
Negative transferStrong source-domain adaptation that actively hurts target-domain transfer. XLM-R-large on zero-shot Urdu.
Degenerate solutionA solution that satisfies the loss function but is useless in practice (e.g. predict all-hate → hate F1 = 0.697 but FPR = 1.0).
Spurious correlationA feature (e.g. religious words) that correlates with a label in training data but not in the real world. Causes biased predictions.
Prompt-based fine-tuningReframing classification as fill-in-the-blank: append "[tweet] This text is [MASK]." and predict the masked word. Uses the pre-trained MLM head to avoid the random-init collapse problem.
VerbalizerA mapping from class labels to vocabulary tokens. E.g. HATE → {hate, bad, vile}; NON-HATE → {normal, fine, okay}. Probabilities for each class are summed via log-sum-exp.
MLM headMasked Language Modelling head — the output layer trained during pre-training to predict masked tokens. Contains rich semantic knowledge about word meaning that benefits prompt-based fine-tuning.
TF-IDFTerm Frequency–Inverse Document Frequency. Weights words by how often they appear in a document vs. how rare they are across all documents. Common words get low weight; distinctive words get high weight.
FuzzyWuzzyPython library for fuzzy string matching. Computes partial string similarity (0–100) between texts. Handles Roman Urdu spelling variation where the same word may be spelled 5 different ways.
Supervised upper boundTraining with the full labelled target-language dataset — represents the best possible performance without transfer constraints. XLM-R-large on all 7,208 Urdu samples: Hate F1 = 0.895.
